# Sync README Structure

Keep the README project tree synchronized without rewriting hand-authored architecture content.

## Workflow

1. Find the workspace root containing `README.md` and `skills/sync-readme-structure`.
2. Finish the requested filesystem changes first.
3. Run `python skills/sync-readme-structure/scripts/sync_readme_structure.py --root .`.
4. Inspect the README diff around the managed markers.
5. Run `python skills/sync-readme-structure/scripts/sync_readme_structure.py --root . --check`.
6. Report whether the structure block changed.

## Rules

- Manage only content between `BEGIN/END AUTO-GENERATED: PROJECT-STRUCTURE` markers.
- Never replace architecture explanations outside the markers.
- Treat additions, removals, renames, and moves as trigger conditions.
- Ignore virtual environments, caches, runtime data, generated bytecode, Git internals, and hidden tool state.
- Include architecture-significant files under `config`, `evals`, `migrations`, `prompts`, `scripts`, `src`, and `tests`.
- Preserve deterministic alphabetical ordering and path-specific descriptions generated by the script.
- If markers are missing or duplicated, stop and repair the README deliberately; do not guess an insertion location.
- Use `--check` in CI or validation tasks. A nonzero exit means README is stale or markers are invalid.

## Trigger Limitation

A skill is invoked while Codex is working; it is not a persistent filesystem daemon. Project-level
`AGENTS.md` instructions must require this skill after structural changes. Changes made outside Codex
must run the script directly or enforce `--check` in CI.
